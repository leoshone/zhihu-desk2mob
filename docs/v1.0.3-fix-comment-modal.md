# v1.0.3 · 评论弹层修复方案

> 基线：**v1.0.0**（真机长期运行的版本）。本版**不含** v1.0.1 / v1.0.2 的改动，
> 详见文末「与 v1.0.1 / v1.0.2 的关系」。

## 1. 背景与问题

在手机上用桌面板知乎时，在回答里点「N 条评论」会打开评论弹层。这个弹层**无法关闭**：
屏幕上找不到任何退出入口，也没有返回路径，只能靠刷新或返回手势离开整个问答页。

用户提出的思路是：点「评论」时把问答页压入历史，让返回功能可以关掉弹层、回到问答页。

## 2. 实测环境

| 项 | 值 |
| --- | --- |
| 设备 | Xiaomi 2211133C，1080×2400，CSS 视口 393×873 |
| 浏览器 | Kiwi（桌面版网站开启）+ 暴力猴 |
| 布局视口 / 缩放 | `innerWidth = 1430`，`visualViewport.scale = 0.25` |
| 脚本反缩放 | `html { zoom: 3.83256 }`（= 1 / scale，见 README 原理） |

> 注意：反缩放让页面同时存在两套坐标 —— `getBoundingClientRect` 与 CSS px 同坐标，
> 而 `elementFromPoint` 用的是**布局坐标**（≈ `rect × zoom`）。做命中测试时极易误判。

## 3. 根因分析

弹层结构（`body` 末尾的 portal）：

```
div[position:fixed, z-index:203, display:flex, flex-direction:column,
    justify-content:center, overflow:hidden auto]   ← 容器，尺寸≈视口（实测 373×734）
  └─ div[max-height:1832px]                          ← 卡片外壳（实测 688×1832，桌面坐标）
       └─ .Modal-content                             ← 内容
  └─ button[aria-label="关闭"]                        ← 关闭按钮，absolute right:-60px
```

四重原因叠加，导致「关不掉」：

1. **卡片高于容器 + 容器垂直居中 → 顶部永久不可达。**
   卡片 1832px、容器 734px，`justify-content:center` 把溢出**上下均分**，
   卡片上移 **549px**（恰好 `(734 − 1832) / 2`）。溢出部分落在滚动原点**之上**，
   而 `scrollTop` 不能为负 ⇒ 向上滚不回来。标题栏与最初几条评论就此永久不可达。

2. **卡片宽于容器 → 右侧被裁。** 卡片按桌面坐标写死 688px，屏幕只有 373px，
   右侧约 315px 被裁掉（表现为评论正文在屏幕边缘被切断）。

3. **关闭按钮被放在卡片外侧。** 知乎桌面版把 ✕ 放在卡片**右侧之外**
   （`position:absolute; top:8px; right:-60px`），在桌面视口下就在屏幕外；
   搬到手机窄视口后更是在屏幕外。

4. **打开弹层不压入任何历史记录。** 而直接进入回答页时 `history.length` 常为 1，
   此时按返回会**直接离开知乎**，而不是关闭弹层。

## 4. 方案

### 4.1 返回键关闭浮层（哨兵历史）

打开弹层时压入一条「哨兵」历史条目；用户按返回 → 触发 `popstate` → **关闭弹层**，
而不是离开页面。

```
弹层打开  → history.pushState({ z2mComment: 1 }, '', location.href)
用户返回  → popstate → 关闭弹层（消费哨兵）
弹层被别的   → 主动 history.back() 撤回哨兵，避免用户多按一次返回
方式关掉
```

**为什么只压历史不够**：知乎自己没有监听 `popstate`，所以只压入条目、不主动关闭弹层，
返回键只会静默消费掉一条记录、弹层依旧留在屏幕上。必须**压历史 + 主动关闭**成对使用。

关闭动作采用两级兜底：

1. 点知乎自己的 `button[aria-label="关闭"]` —— **`.click()` 不走命中测试，
   按钮即使被放在屏幕外也照样生效**（这是能关掉的关键）；
2. 失败则补发 `Escape`（在 `document` 与 `activeElement` 各派发一次），300ms 后复查再补一次。

### 4.2 溢出定位修正

**只在「卡片比容器更大」这种越界情形下动手**，不越界的弹层一律不改：

- 卡片**高于**容器 → 容器改为 `justify-content: flex-start`（顶部对齐，标题栏回到可达区域）；
- 卡片**宽于**容器 → 卡片加 `max-width:100% / width:auto / align-self:stretch`（收进屏幕宽度）。

不加这层限制的话，会把本来正常垂直居中的小弹窗顶到屏幕顶部。

### 4.3 关键安全设计

| 风险 | 处置 |
| --- | --- |
| 弹层被其它方式关掉后，历史里留下哨兵 → 用户多按一次返回 | `dropGuard()` 主动 `history.back()` 撤回 |
| 用户在弹层里导航过（点了链接），撤回动作会**撤销用户的导航** | 撤回前校验 `history.state.z2mComment === 1`，确认哨兵仍是当前条目才回退 |
| 用户刚点开评论就马上按返回，哨兵还没压入 | 弹层开合同步挂在 `MutationObserver` 回调里（不走 300ms 去抖），另加 800ms 兜底轮询 |
| 站点的浮层组件残骸（`display:none`）被误判为「打开」 | 判据为 `.Modal-content` **存在即打开** —— 实测该弹层关闭后约 400ms 内会被真正移除，此判据成立 |
| 浮层定位修正反复写样式 | 写入前先比 `getBoundingClientRect`，且只在越界时写；写前检查内联值，避免无谓改动 |

### 4.4 开关

```js
const CFG = {
  commentBack: true,        // 返回键关闭评论弹层
  fixCommentLayout: true,   // 溢出定位修正
};
```

## 6. 验证

均在真机（Kiwi + 暴力猴实装版本）上跑通：

| 场景 | 结果 |
| --- | --- |
| 打开弹层 → 返回键关闭 | 通过 |
| 打开弹层 → `Escape` 关闭（哨兵被主动撤回，无残留） | 通过 |
| 打开弹层 → 点原生「关闭」按钮关闭（同上） | 通过 |
| 关闭后再次打开 → 返回键仍可关闭 | 通过 |
| 定位修正：卡片宽度不超出容器、顶部与容器顶部对齐 | 通过 |

修复前后对照（大卡弹层实测）：

| | 修复前 | 修复后 |
| --- | --- | --- |
| 容器 | `[0,0,373,734]`，`justify-content:center` | `justify-content:flex-start` |
| 卡片 | `[0,−549,688,1832]` | `[0,0,393,1832]` |
| 标题栏 / 关闭入口 | 位于 y = −549，屏幕外且滚不回来 | 标题栏回到 y = 0，可见 |
| 正文宽度 | 688px 中仅可见 373px，右侧被裁 | 393px 全可见，正常换行 |

> 卡片高度取决于已加载的评论条数，因此**垂直溢出并非每次都能复现**（评论少时卡片不溢出，
> 此时不应做任何改动）。该分支已用受控夹具（人造同构 DOM + 调用脚本导出的同步函数）
> 做确定性单元测试覆盖，线上只用于验证「实际命中」。

## 7. 已知问题

1. **弹层自带的「关闭」按钮仍在屏幕外。** 它由知乎放在卡片右外侧（`right:-60px`）。
   搬进屏幕内会压住标题栏右侧的「默认 / 最新」标签页；且其 `z-index`
   被限制在卡片 `z-index:1` 的堆叠上下文内，在根 `zoom` 下实测被头部行覆盖。
   因此未强改，退出统一由返回手势承担。

2. **图片查看器在 v1.0.0 下会跑到屏幕外**（该问题由 v1.0.1 修复），本版未包含。

## 8. 与 v1.0.1 / v1.0.2 的关系

- v1.0.1：修正回答/问题区块宽度不一致、图片查看器居中
- v1.0.2：治理文字截断（box-sizing + max-width + overflow-x hidden）、长 token 断行

这三版是**两条独立分支**：v1.0.3 从 v1.0.0 起步，因此**不包含**上述改动。
若需要「v1.0.2 的全部改进 + 本版弹层修复」，可另开一版把两条线合并。
