# v1.0.4 · 评论区发布框修复方案

> 承接 [v1.0.3](v1.0.3-fix-comment-modal.md)。本版针对**评论区发布框**（写评论那个输入框）
> 的两个布局缺陷：一个把发布框撑得很高，一个让「发布」按钮跑到屏幕外。

## 1. 背景

在手机上浏览专栏／回答时，底部的评论发布框被撑得很高，明显比应有的高度多出一截。
用户的要求是：把「同时发布到想法」这个选项（单选框 + 文案）去掉。

## 2. 实测环境

| 项 | 值 |
| --- | --- |
| 设备 | Xiaomi 2211133C，1080×2400，CSS 视口 393×873 |
| 页面 | `zhuanlan.zhihu.com/p/...`（专栏文章，评论区在页脚） |
| 触发条件 | **选项只在评论输入框获得焦点后才渲染**（未聚焦时 DOM 里没有它） |

> 这个「聚焦才出现」的特性值得记下来：不点进输入框就查不到该元素，
> 会误判为「页面上没有这个选项」。

## 3. 问题一：「同时发布到想法」被压成竖排，把发布框撑高

### 现象

| 元素 | 尺寸 |
| --- | --- |
| 选项包裹层 | **宽 0px**、高 121px |
| 选项文案（`span`，7 个汉字） | **13 × 121px** —— 即一个字一行，竖排 |
| 评论发布框 | 高 **185 ~ 219px** |

文案的父层被压到 0 宽，于是 7 个汉字逐字换行成一列，整行高度被拉到 121px，
发布框随之膨胀。

### 根因

包裹层是 flex 子项，其 `min-width` 被压到 0，因而可以收缩到 0 宽；文案又允许换行。
**这条 `min-width: 0` 正是本脚本自己加的** —— v1.0.0 的 CSS 里有
`main div, main section, … { min-width: 0 !important }`（原本用于消除知乎写死的 min-width），
而该选项确实位于 `main` 之内（实测 `closest('main')` 命中）。所以这是脚本自身规则的副作用，
不是知乎的问题。

### 方案

按文案定位，向上收成「除该文案外不含其它文字」的最大祖先，然后 `display: none`。
这样能**连它左侧的单选框图标一起隐藏**，又不会误伤同一行右侧的「发布」按钮
（后者所在层级的文案里还有「发布」二字，不满足收敛条件）。

不按类名定位的原因：该包裹层的类名是 emotion 生成的 hash（`css-tqtem1`），
会随知乎构建变化。

### 验证

| | 修复前 | 修复后 |
| --- | --- | --- |
| 选项包裹层 | 0 × 121（内容竖排溢出） | `display: none` |
| 发布框高度 | 185px | **94px** |

## 4. 问题二：「发布」按钮右侧超出屏幕

### 现象

「发布」按钮宽 62px，但右边缘超出屏幕 **20px**，只露出 42px。

### 根因

按钮所在的那一行：可用宽 **225px**（`clientWidth`），内容却需要 **304px**（`scrollWidth`），
超出 79px。行内两个子元素**互不相让**：

| 子元素 | 宽度 | flex | 来源 |
| --- | --- | --- | --- |
| 编辑区（工具栏） | 218px | `flex: 0 0 auto` | 知乎自己的样式，不收缩 |
| 「发布」按钮 | 62px | `flex: 0 0 auto` | **本脚本**的 `main button { flex: 0 0 auto }` |

两个都是 `flex: 0 0 auto`（不收缩），行放不下就把按钮挤了出去：
先挤出本行容器 55px，再越过屏幕 20px。中间的控件小容器被压到 7px 宽，按钮照样按 62px 绘制。

> 脚本里 `main button { flex: 0 0 auto }` 的初衷是「按钮绝不能被压成竖排文字」，
> 这个初衷没错；问题出在同一行里没有任何元素可以收缩。

### 方案对比（实测）

让这一行放得下按钮，有两种改法：

| 方案 | 做法 | 按钮可见宽 | 发布框高度 |
| --- | --- | --- | --- |
| A 允许换行 | 行加 `flex-wrap: wrap` | 62 / 62px ✅ | 94 → **118px**（+24） |
| **B 编辑区可收缩** | 编辑区改 `flex: 1 1 auto` + `min-width: 0` | 62 / 62px ✅ | **94px（不变）** ✅ |

选 **B**：按钮完整可见，且不增加高度；工具栏经截图核对未被压坏。
A 虽然更「保守」（不压缩任何内容），但要牺牲 24px 高度，而这一版的出发点正是压掉多余高度。

### 定位方式

同样不能用 hash 类名。规则是：**从「发布」按钮往上找第一个「自身溢出、且首个子元素占了大半
内容宽」的行**。

这条规则能跳过按钮直属的那个 7px 宽控件容器（它虽然也「溢出」，但首个子元素宽度为 0），
准确命中 225px 宽的那一行。另加一条约束：**只在该行宽度 ≤ 脚本列宽时动手**，
避免影响桌面宽度下的正常布局。

## 5. 代码改动

| 位置 | 改动 |
| --- | --- |
| 配置 | 新增 `CFG.hideIdeaOption` / `CFG.fitPublishButton` |
| 脚本主体 | 新增 `hideIdeaOption()` 与 `fitPublishButton()`，接入 `tick()` |

`hideIdeaOption` 用 XPath（`//*[contains(., '…')]`）按文案定位，避免遍历全部元素；
两者都缓存已处理节点，SPA 重建后靠 `isConnected` 自动重找。

## 6. 验证

真机（Kiwi + 暴力猴实装版本）跑通：

| 场景 | 结果 |
| --- | --- |
| 选项被隐藏（包裹层 `display:none`） | 通过 |
| 发布框保持紧凑高度（94px ≤ 130px） | 通过 |
| 「发布」按钮未被误伤，仍可见 | 通过 |
| 「发布」按钮完整落在屏幕内（右溢 −37px，可见 62/62px） | 通过 |
| v1.0.3 评论弹层行为无回归 | 通过 |

## 7. 说明

- 这两项都可以用配置开关单独关闭（`CFG.hideIdeaOption` / `CFG.fitPublishButton`）。
- 隐藏「同时发布到想法」是产品取舍：该选项用于把评论同时发成「想法」，
  在手机窄列下它无法正常排版，且属低频功能。若需要保留，可把
  `CFG.hideIdeaOption` 设为 `false`，但发布框会回到较高状态。
