# v1.0.5 · 发布框头像与弹层按钮修复

> 承接 [v1.0.4](v1.0.4-fix-comment-composer.md)。这一版处理评论发布框的头像，并顺带修掉
> 弹层内「发布」按钮被压成竖排的问题 —— 后者是排查头像时发现的。

## 1. 问题

发布框最左侧的头像被**拉高**：宽 40px，高却是 **122px**（等于整行高度），图片明显纵向拉伸。

## 2. 根因：是脚本自己造成的

对比实验（同一页面，只切换脚本 CSS）：

| | 发布框头像 | 评论列表头像尺寸分布 |
| --- | --- | --- |
| 脚本 CSS 生效 | **40 × 122**（拉伸） | 24×24 × 70，**24×0 × 8** |
| 关掉脚本 CSS | **40 × 40**（正方形） | 24×24 × 78 |

元凶是 v1.0.0 就有的这条通用规则：

```css
img, video { max-width: 100% !important; height: auto !important; }
```

它的本意是「别让内容图片撑破 393px 的窄列」。但 `height: auto !important` 是**无差别**施加的，
它顶掉了知乎写给头像的固定高度；而头像所在的 flex 行是 `align-items: normal`（即 stretch），
高度变成 auto 之后就被拉到整行高 —— 40×122。

同一条规则还让 8 个头像的高度塌成 0（`24×0`），只改头像高度不改宽度，于是变成一条窄片。

## 3. 修法

把 `.Avatar` 从这条通用规则里排除：

```css
img:not(.Avatar), video { max-width: 100% !important; height: auto !important; }
```

其余图片保持原样 —— 站点写了宽高比的内容图，正是靠 `height: auto` 才不会在 `max-width`
收窄后变形；头像则是「固定尺寸的 UI 元素」，本来就不需要这条规则。

实测效果：发布框头像回到 40×40，8 个 `24×0` 的头像一并恢复成 24×24。

## 4. 尺寸取 40 还是 24

知乎给发布框头像是 **40px**，而评论列表里的头像是 **24px**。

按使用者要求「与评论里其他人的头像一样大」，本版把发布框头像缩到 **24×24**。
这是**刻意偏离站点设计**（40px 是知乎对发布框这一块的选择），所以留了开关：

```js
matchComposerAvatar: true,   // 设为 false 则保留知乎原本的 40px
composerAvatarSize: 24,
```

定位方式：发布框那个头像只有 `Avatar` 这个通用类，旁边的类名是 emotion hash，
CSS 无法表达「与发布按钮同一行的那个头像」，所以走结构 ——
从「发布」按钮往上找第一个内含 `img.Avatar` 的祖先，那个头像就是发布框的。

## 5. 顺带发现：弹层内的「发布」按钮是竖排的

排查头像时截图看到，评论弹层里的「发布」按钮被压成 **49×58**，文字折成两行「发 / 布」。

原因：脚本的按钮规则写的是 `main button, header button`，而**弹层挂在 body 的 portal 里、
不在 `main` 内** —— 这条规则漏掉了整个弹层区域。于是弹层内的按钮保持了知乎的
`white-space: normal`，宽度被挤到 49px 时文字就竖排了。

修法是同一条规则补上弹层：

```css
main button, header button, .Modal-content button { white-space: nowrap !important; }
```

刻意**只加 `nowrap`，不加 `flex: 0 0 auto`**：后者会让按钮拒绝收缩、把整行撑溢出
（这正是 v1.0.4 里页面级发布框踩过的坑）。实测弹层内「发布」恢复 62×30 横排，
右边缘距屏幕还有 40px。

## 6. 代码改动

| 位置 | 改动 |
| --- | --- |
| CSS | `img` → `img:not(.Avatar)`；按钮 `white-space` 规则补上 `.Modal-content` |
| 配置 | 新增 `CFG.matchComposerAvatar` / `CFG.composerAvatarSize` |
| 脚本主体 | 新增 `matchComposerAvatar()`，并把「找发布按钮」抽成 `publishButton()` 供两处复用 |

## 8. 一点反思

这两处都不是知乎的问题，而是**脚本自己的通用规则误伤**：

- `img { height: auto !important }` —— 无差别地改掉了站点固定尺寸的 UI 图片；
- 按钮规则只写 `main ...` —— 漏掉了挂在 body portal 里的弹层。

写「通杀式」规则时，作用范围要么收窄到真正需要的元素（内容图），要么补全所有挂载点
（`main` 之外的 portal）。排查这类问题的顺序，值得先怀疑脚本自己，再去怀疑站点。
