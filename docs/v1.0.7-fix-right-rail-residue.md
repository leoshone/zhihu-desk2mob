# v1.0.7 · 清掉右边缘的侧栏/页脚残留

> 承接 [v1.0.5](v1.0.5-fix-avatar-and-modal-publish.md) / [v1.0.6](README)。这一版治的是首页
> 右边缘那条**逐字竖排**的残留文字（帮助中心、举报中心、关于知乎、服务热线…）。

## 1. 现象

首页右边缘有一条约 40px 宽的竖条，里面是**一个汉字一行**的
「帮助中心 / 举报中心 / 关于知乎 / 服务热线」等页脚链接，只露出最右边一点。

## 2. 根因：侧栏被挤成 0 宽，文字却照旧溢出

实测结构：

```
.Topstory-container   (flex row, 373px)
├── DIV.Topstory-mainColumn        341px   ← 正文列
└── DIV.css-bkewaf                 w=0     ← 侧栏整个塌成 0 宽
      ├── DIV.HotSearchCard       「大家都在搜…」
      ├── DIV.Card                「盐言作者平台…」「付费咨询…」
      ├── DIV.Card.css-1iaxl4o    「推荐关注…」（这张还有 32px）
      └── FOOTER.css-2pfapc       「帮助中心…」 rect = { x:377, w:0, h:2113 }
```

两个条件合起来造成了那条竖排：

1. **宽度塌成 0**：窄列重排把侧栏挤没了宽度，于是 `white-space: normal` 让**每个字符各自换行**
   —— 于是「帮助中心」变成 4 行、整个页脚 2113px 高。
2. **`overflow: visible`**：宽度为 0 的盒子**不裁剪**内容，所以文字照旧画出来，溢出到屏幕上。

也就是说：**不是文字没被隐藏，而是一个 0 宽的盒子在照常显示它的文字。**

## 3. 为什么现成的 `hideSideRails` 没盖住

`hideSideRails` 本来就是干这个的（隐藏「内容列之后」的侧栏），但它的判据是**几何式**的：

```js
r.width >= 80 && r.width <= 420 && r.height >= 300
```

侧栏塌成了 **w=0** ⇒ 第一个条件直接不成立 ⇒ 整条侧栏被放过。

## 4. 修法：给判据补上「塌陷」这一形态

```js
const normalRail    = r.width >= 80 && r.width <= 420 && r.height >= 300;      // 形态 A：正常侧栏
const collapsedRail = r.width <= 4 && r.height >= 60 && (k.textContent || '').trim().length > 0;  // 形态 B
if ((normalRail || collapsedRail) && /* 落在该行右半边 */) k.style.display = 'none';
```

形态 B 的三个条件都是必要的：
- `width <= 4`：它塌了；
- `hasText`：**有文字可溢出**才叫残留（纯图标/占位元素宽度为 0 是正常的，不该动）；
- `height >= 60`：排除那些细小的塌陷包装层。

同时保留「必须落在该行右半边」这条（v1.0.6 加的），避免把左右等宽版式的正文列一起隐藏。

**没有单独去隐藏 `<footer>`**：页脚只是这条侧栏里的一个成员，真正该消失的是整条侧栏
（里面还有热榜、广告卡、推荐关注 —— 全是同样看不懂的竖排）。只藏页脚会留下其余的。

## 5. 验证（真机）

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| `帮助中心` 可见性 | visible，rect `{x:381,w:0,h:104}` | **不可见**（祖先 display:none） |
| `举报中心` / `关于知乎` / `服务热线` | 均可见 | 均不可见 |
| 右边缘「宽≤4 却含文字」的可见元素 | 9 个 | **0 个** |
| 正文列 | 可见 341px | 可见 341px（**没被误伤**） |
| 首页信息流条目 | 12 条 | 12 条 |

`scripts/test-rightrail.js` 覆盖以上断言，且带回退保护：**同时断言正文列仍在、宽度正常、
信息流条目仍在** —— 防止「隐藏」用力过猛把正文也藏了。

## 6. 顺带发现（本版未动）

写「同步到圈子」的输入卡片里，有一个**同类残留**：「同步到圈子」这个选项标签同样塌成
0 宽、高 95px、逐字竖排（实测 `rect {x:298, w:0, h:95}`，其所在行只有 49px 可用宽）。
它在页面顶部就能看到，属于**既有问题**（1.0.0 起就有），不是本版引入。

它与 v1.0.4 处理过的「同时发布到想法」是同一形态，但**性质不同**：
那是一个低频附带选项（当时按用户决定隐藏），而「同步到圈子」是**发到圈子的功能开关**，
隐藏它就等于去掉一个功能。因此本版没有擅自处理，留待决定：
既可像「同时发布到想法」一样隐藏，也可试着把这个拥挤的行重新排开（需要取舍让谁让位）。

`test-rightrail.js` 会把这类**别处的**同类残留打印成提示但不作为失败项 —— 它不在本次报告范围。
