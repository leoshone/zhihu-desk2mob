# v1.0.8 · 修掉「打开页面后被自动放大，得双指捏合才能缩回去」

## 1. 现象

打开知乎页面后，整页被**放大数倍**（截图里「知乎」logo 占满半个屏幕），
必须双指捏合缩回去才能正常看。而且每次都要捏一次。

## 2. 复现（真机取证）

把浏览器比例设成 1（= 桌面模式的反缩放不再生效），而脚本写下的 `html{zoom}` 仍是 `3.63922`：

```
设 scale=1 后: { scale: 1, vvW: 358, htmlZoom: "3.63922", bodyW: 393 }
```

于是整页被放大 3.64 倍 —— 正是用户看到的样子。

## 3. 根因：反缩放只算一次，而缩放变化它收不到通知

脚本为了让桌面版在手机上以正常字号显示，会写 `html{zoom: 1/scale}`
（桌面模式把布局视口锁在 ~1430px 并整体缩小到 0.25，不反缩放则文字小到看不清）。

问题在于它**只在 `window.resize` 时重算**。而浏览器的缩放变化
（包括加载后把用户上次记录的捏合比例恢复回来）**只触发 `visualViewport.resize`**，
`window.resize` 不触发 —— 实测：连续改变页面比例，`window.resize` 计数**恒为 0**，
`visualViewport.resize` 正常触发。

于是：加载时按 `scale≈0.275` 定下 `zoom≈3.64` → 之后浏览器把比例恢复成 `≈1`
→ 脚本毫不知情，`zoom` 停在 3.64 → **整页放大数倍**。

顺带还量到同一页面连续三次全新加载，终值竟是 `3.63922 / 3.31082 / 3.63922`
（`innerWidth` 在 1301 与 1430 之间变）—— 说明加载后 overview zoom 仍在落定，
一次性的算法本来就跟不住。

## 4. 改法：分三段，既不漏也不算过头

```js
// ① 加载后的稳定窗口内（3s）：跟随 scale 重算 —— overview zoom 此时还在落定
// ② 窗口之后：scale 变化只可能是用户在捏合 → **不跟随**（跟随会跟用户抢，让他捏不动）
// ③ 例外：比例回到正常（>= 0.9）→ **必须撤掉 zoom**，否则就是上面那个「整页放大」
const SETTLE_MS = 3000;
function applyZoom() {
  const s = (window.visualViewport && visualViewport.scale) || 1;
  if (s >= 0.9) { if (curZ !== 1) { curZ = 1; removeZoom(); } return; }
  if (curZ !== 1 && Date.now() - startedAt > SETTLE_MS) return;   // 不跟用户的捏合
  ...
}
window.addEventListener('resize', applyZoom);
window.visualViewport.addEventListener('resize', applyZoom);   // ← 关键：补上这条
```

为什么不是「每次缩放变化都重算」：那样等于让内容永远铺满屏宽，
用户**根本捏不动**（捏了立刻被拉回）。为什么又必须补监听：否则浏览器改比例时脚本收不到，
就停在旧的 zoom 上（本次的 bug）。稳定窗口正好把「加载后的落定」与「用户的捏合」分开。

## 5. 验证（真机，`scripts/test-counterzoom.js`）

先人为把比例设成缩小态再加载，确保一定施加了反缩放，然后：

| 步骤 | 修复前（1.0.7） | 修复后（1.0.8） |
| --- | --- | --- |
| ① 加载稳定后 | 内联 zoom `2.49306`（scale 0.401） | 同上 |
| ② 稳定期后 scale→0.5 | zoom 不变 ✓ | zoom 不变 ✓（**不跟用户抢**） |
| ③ **scale→1（正常）** | zoom **仍是 2.49306** ✗ 整页放大 | **zoom 已移除**（内联 style 为空）✓ |

全套回归（真机）：反缩放 5/5、右边缘 9/9、头像 8/8、发布框 8/8、评论弹层 23/23、定位夹具 10/10。

## 6. 一点提醒

`getComputedStyle(document.documentElement).zoom` **不能**用来判断「脚本有没有施加 zoom」：
未设置内联 zoom 时它返回的是 **dpr**（本机实测 `3.02348`），看上去像有 zoom 其实没有。
判据只能是 `documentElement.style.zoom`（内联）。这个坑在写测试时踩到了，已记进测试注释。
