# v1.2.0 · 块状版式铺满整列：去掉两侧灰边（保留块间灰缝）

## 1. 需求

用户反馈：首页 / 问答 / 专栏都是**块状风格**，但在手机上内容列**两侧各留一条灰色空隙**，
很浪费屏幕。要求**去掉两侧灰色空间**，但**块与块之间的灰色间隔要保留**。

## 2. 取证（真机 CDP 实测）

- 「灰色」= **`body` 背景 `rgb(244, 246, 249)`**。
- 两侧留白各 **26px** = 本脚本 `.App-main` 的 `10px`（脚本自己加的）＋ 知乎最外层容器的 `16px`：

| 页面 | 那个 16px 容器 | 用什么选到它 |
| --- | --- | --- |
| 首页 | `.Topstory-container` | 稳定类名，直接选 |
| 专栏 | `.css-kjzwqj` | **emotion hash** → 改用结构选择器 `.Post-content > div` |
| 问答 | `.css-1gl8cva` | **emotion hash** → 改用结构选择器 `.QuestionPage > div` |

- 首页右列另有一个 `.Topstory-mainColumn { margin-right: 10px }`，也要清掉，否则右侧仍留 10px。
- **白色「块」自身带内边距**（首页 16px / 专栏 20px / 问答 22px）⇒ 去掉外侧留白后，
  块铺满整列而**文字仍有呼吸感，不需要再补内边距**。这一条是先把留白与内边距分别量清楚
  才敢下的结论（一开始误以为卡片内边距为 0，量了才发现那是内层 `.ContentItem` 的 padding）。
- **块间竖直灰缝来自卡片自己的 `margin-bottom: 10px`** ⇒ 只改横向必然保住它，无需额外处理。
- ⚠️ `.App-main` 与那个 16px 容器之间还夹着 **3~4 层包装 div**（含混淆类名），
  所以 `App-main > *` / `> * > *` 这类**按深度写的选择器打不到**，必须按类名或结构定位。

## 3. 改法与实测结果（列宽 358）

```css
.App-main { padding-left: 0 !important; padding-right: 0 !important; }
.Topstory-container, .Post-content > div, .QuestionPage > div {
  padding-left: 0 !important; padding-right: 0 !important;
}
.Topstory-mainColumn { margin-left: 0 !important; margin-right: 0 !important; }
```

| 页面 | 改动前 | 改动后 | 文字内缩 |
| --- | --- | --- | --- |
| 首页 | 块 26..332（306 宽）| **0..358（358 宽）** | 16px |
| 专栏 | 10..348（338 宽）| **0..358（358 宽）** | 20px |
| 问答 | 10..348 | **0..358（358 宽）** | 22px |

块间竖直间隔实测**不变**（首页仍为 10px）。开关：`CFG.bleedEdges`（关掉退回原来的两侧 10px 留白）。

## 4. 顺带解决「已知未修」第 2 条：竖排「同步到圈子」

原来记录的「写想法」卡片里那处竖排残渣，本次量清了：那一行只有 234px 可用宽，
这个「发到圈子」的开关被挤成 **0 宽**（`rect {x:298, w:0, h:95}`），7 个汉字因此逐字竖排。

它是**发到圈子的功能开关**，隐藏等于去掉功能——属产品取舍。**用户 2026-09-30 明确要求去掉**，
故新增 `CFG.hideCircleSync`，定位方式复用 `hideIdeaOption` 那一套：
按文案 XPath 找到最内层节点 → 向上收成「除该文案外不含其它文字」的最大祖先 → `display: none`
（这样能带上它自己的图标，又**不会误伤同一行右侧的「发想法」按钮**——那个按钮的祖先文案里还有「发想法」）。

## 5. 「发想法」按钮：现已完整收进屏幕（v1.2.1）

去掉两侧留白后，这个按钮从「越出屏幕 35px」减轻到「越出 9px」。用户随后要求**完整显示、且不贴边**，
于是继续查到底 —— 根因有**三个，缺一不可**：

1. 知乎给按钮写了**固定宽度 `75px`**：把它的内边距改成 8px 后，计算宽度**仍是 74.9998px**
   ⇒ 「只收窄内边距」无效（宽度根本不随内边距走）。
2. 它自带 **`margin-left: 20px`**：把按钮从所在行的 `272` 顶到 `292`。
3. 文字本身 `45px` + 左右内边距 `18px×2` = `81px`，而它所在盒子只有 `66px` 宽 ⇒ 只能溢出。

**解法**（`CFG.fitIdeaButton`）：`width: auto`（把宽度交还给内容）＋ `margin-left: 0` ＋ 内边距收到 `12px`。

实测：按钮 `292..367`（越出 9px）→ **`272..341`** —— **完整可见，距屏幕右缘 17px**，
且与块内其它内容的右边界（342）基本对齐。

### 试过但无效 / 被否掉的路子（别重复走）

| 路子 | 结果 |
| --- | --- |
| 只收窄按钮内边距 | 宽度被写死 75px，纹丝不动 → 无效 |
| 给父盒 `flex: 0 0 auto` | 越界 9 → **88px（更糟）** |
| 父盒加 `margin-right` / 所在行加 `padding-right` | 无效 |
| 让它所在那一行换行（`flex-wrap: wrap`）| 可完全进屏（越界 −20px），但按钮**独占一行**，用户否掉 |
| 用 `:has()` 选它的父盒 | Kiwi 确实支持（`CSS.supports('selector(:has(*))')` 为真），但在这个布局里帮不上忙 |

> ⚠️ **排查「元素越界」时，先读它自己的 `margin` 与写死的 `width`** —— 本次两个关键事实
> （`margin-left: 20px`、`width: 75px`）都不是 padding 造成的，**只改 padding 永远调不动**。
