# v1.2.2 · 首页信息流：封面缩略图改小 + 正文真正「右 + 下」环绕

## 1. 需求

用户：首页列表里**图片太大**，改小一些；并且要求文字在图片的**右侧与下方环绕**。

## 2. 取证（真机 CDP 实测）

- 知乎的封面是 `.RichContent-cover`：**`float: left`**，固定 **190×105** 盒子
  （内有 `position: absolute` 的 `.RichContent-cover-inner`，图片 `object-fit: cover` 居中裁切）。
  所以「文字绕在图片右侧」**本来就是它的设计**，不是缺陷。
- 真正的问题是尺寸：**190px 占内容列 326px 的 58%**，绕在右侧的文字只剩 **136px** ⇒ 每行仅 7~8 字。
- **「下方不环绕」的根因（关键）**：`.RichContent-inner` 的 `overflow` 是 **`hidden`** ——
  这会让它成为一个 **BFC**（块级格式化上下文）。**BFC 的盒子会被整体挤到浮动元素旁边，
  永远不会在浮动下方回宽** ⇒ 文字一路都是窄列。
  逐行实测确认：改动前正文 8 行**全部**从 `L=154` 起（封面右缘 136 + 18px 间距），
  即使远低于封面底边也不回宽。
- 试过 **6 条**候选规则均**无效**（都没碰到那个 BFC）：
  `span{display:block}`、`.RichContent-inner{display:block}`、两者同时、
  `.RichContent-cover{overflow:visible}`、`.RichContent{overflow:visible}`。

## 3. 改法与实测

```css
/* 封面改小 */
.RichContent-cover { width: 100px !important; height: auto !important; aspect-ratio: 190 / 105 !important; }
.RichContent-cover-inner { width: 100% !important; height: 100% !important; }
.RichContent-cover img { width: 100% !important; height: 100% !important; }
/* 解开 BFC —— 这才是「下方也环绕」的开关 */
.ContentItem .RichContent-inner { overflow: visible !important; }
```

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 封面 | 190 × 105 | **100 × 55** |
| 图片右侧文字可用宽 | 136px | **226px** |
| 逐行左缘 | 8 行全是 154（**0 行**回宽）| 首行 198，其后 **16、16…（已回到全宽）** |

开关：`CFG.feedThumbWidth`（宽度，设 0 则不干预）与 `CFG.wrapAroundThumb`（是否解开 BFC）。

### 试过但无效 / 错误的路子（别重复走）

| 路子 | 结果 |
| --- | --- |
| `.RichContent-cover-inner { position: static }` | ❌ **图片被推出屏幕**（实测 `L=-44`），卡片只剩一块浮动占位 |
| 用 `zoom` 缩放封面 | ❌ 无效：浮动盒仍是 190×105，文字列**不会**变宽 |
| 只解 `overflow` 而不改尺寸 | ⚠️ 会回宽，但图片仍是 190px，依然太大 |
| 给正文块 `display: block` / 给容器 `overflow: visible`（外层） | ❌ 都无效，必须打到 `.RichContent-inner` 这一层 |

> ⚠️ **排查「浮动旁的文字不在下方回宽」时，先看正文容器的 `overflow` / `display` 是否让它成了 BFC。**
> 这是本次唯一的关键 —— 前面所有「改 display、改外层 overflow」的尝试都白费，因为根因在内层那个 BFC。
