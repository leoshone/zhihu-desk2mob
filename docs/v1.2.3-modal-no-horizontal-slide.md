# v1.2.3 · 评论弹层不再能被横向滑动推走

## 1. 现象

用户反馈：弹出的评论**可以往左滑动** —— 一划整个弹层左移，**左边被裁**、右边露出底下的页面。

## 2. 取证（真机 CDP 实测）

- 弹层 `.Modal-content` 宽度**正确**（358），但位置是 **`-60..298`** —— 整体左移了 60px。
- 它所在的固定层 `.css-zbtg51`（`position: fixed`，`0..358`）：
  **`clientWidth 358` / `scrollWidth 418` / `scrollLeft 60.04`** ⇒ 这一层被**横向滚动了 60px**。
- `418 − 358 = 60`，恰好是知乎那个**故意放在屏幕外的原生「关闭」按钮**
  （`right: -60px`，即「已知未修」第 1 条）—— 它让这一层的内容比层自身宽 60px。

## 3. 根因：两因叠加，责任都在脚本自己这边

1. `capFixed()` 对「宽于列宽的 fixed 元素」设了 **`overflow-x: auto`** —— 这一层因此成了**可横向滚动**的容器。
2. 那段 60px 溢出**平时是看不见的**（关闭按钮在屏幕外），`auto` 一开就把它变成了**可滚区域**。

⇒ 用户一划就能把整个弹层推走 60px，**且划出去后回不来**（`scrollLeft` 停在 60，左侧内容永久被裁）。

> 这条与 v1.2.0 的「去两侧灰边」无关，也**不是**此前那个 `pageScaleFactor` 残留
> （那次是 `visW < innerWidth`；这次 `visW == innerWidth == 891`，是**层内**的横向滚动）。

## 4. 改法与实测

把 `capFixed()` 里的 `e.style.overflowX = 'auto'` 改成 **`'hidden'`**（纵向滚动仍由这一层承担）。

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 层 `overflow-x` | `auto` | **`hidden`** |
| 层 `scrollLeft` | 60 | **0** |
| 弹层位置 | `-60..298` | **`0..358`** |
| 用户能否横向滑动 | 能 | **不能** |

### ⚠️ 本次顺带查清：`test-counterzoom` 的**加载期**断言（①②）也是间歇失败的

实测同一份代码多次运行，`fitRatio` 序列有时是完美的 `[1,1,1,…]`，有时开头两个采样是
**`1.1577`**（内容比视口宽 16%），随后收敛到 1 —— 于是①（全程不超宽）与②（视觉尺寸稳定）
会报 FAIL，`worstFit 0.158` / `jitter 15.8%`。

**已做 A/B 排除本次改动**：把 v1.2.2 的发布件装回真机跑三次 —— 一次完美、**一次复现同样的瞬变**。
⇒ 该瞬变是**既有的、间歇的加载期竞态**，与版本无关。

**看到 ①② 失败先重跑**，别当成产品回归；重跑前记得该测试会残留页面比例（见 `scripts/README.md`）。
