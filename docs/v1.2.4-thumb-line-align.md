# v1.2.4 · 首页封面：按「正文行数」定尺寸 + 上下与文字对齐

## 1. 需求

用户：首页信息流里**图片跟文字上下没对齐**；图片当时是 100px 宽，**能否改成「3 行文字高度」（宽度跟随变），
并且上下跟文字对齐？**

## 2. 取证（真机 CDP 实测）

- 正文**行高 = 28px**（= 16px × 1.75，本脚本自己定的字号规则，见 `zhihu-desk2mob.user.js` 的 readability 段）。
- v1.2.2 设定的 100px 宽 → 封面高 **55px = 1.97 行**（差 1px 才够 2 行）。
- **「上下没对齐」的真正原因**：图片顶与**行框顶**本来就重合，但文字有**半行距 6px**
  （`(行高 − 字号) / 2 = (28 − 16) / 2`），文字的**视觉顶**在行框顶下方 6px ⇒ 看起来图片比文字高出一截。
  实测：图片顶 `118`、文字首行视觉顶 `124` ⇒ 偏差 **−6px**。

## 3. 改法

由**行数反推**尺寸（`CFG.feedThumbLines`，默认 `3`；设 `0` = 不干预、保持知乎原样）：

```css
:root { --z2m-line: 28px; }                     /* 与上面的字号规则一致 */
.RichContent-cover {
  height: calc(var(--z2m-line) * 3) !important;  /* = 84px */
  width: auto !important;
  aspect-ratio: 190 / 105 !important;            /* 宽度按原比例跟随 */
  margin-top: 4px !important;                    /* 对齐用，见下 */
}
.RichContent-cover-inner { width: 100% !important; height: 100% !important; }
.RichContent-cover img { width: 100% !important; height: 100% !important; }
```

**对齐量为什么要 4px**：半行距是 6px，但拿 6px 实测得 **+2px**；逐档量下来 **4px** 时
「顶偏差」与「底偏差」**同时为 0** —— 所以取实测值，不取理论值。

## 4. 实测

| 档 | 图片 | 图片右侧文字可用宽 | 顶偏差 | 底偏差 |
| --- | --- | --- | --- | --- |
| v1.2.2（100px 宽）| 100 × 55（1.97 行）| 226px | **−6px** | −6px |
| 2 行 | 101 × 56 | 225px | 0 | 0 |
| **3 行（当前默认）** | **152 × 84** | **174px** | **0** | **0** |

真机复核（实装 1.2.4、首页）：封面 **152 × 84**、**高 ÷ 行高 = 3.000**、**顶偏差 0px**；
图片底边落在第 3 行边界上，其下正文回到全宽。

> **权衡（如实说明）**：3 行档图片更醒目，但绕排文字从 225px 缩到 **174px**（每行约少 3 字）；
> 2 行档的图片尺寸与 v1.2.2 那档基本一致（101 vs 100），文字列仍是 225px。
> 换档只需改 `CFG.feedThumbLines` 一个数字（2 / 3 / 4）。

## 5. v1.2.5 修正：让旁排正好是 3 行（图片**不需要**缩小）

**现象**（用户）：图片看起来占了 **4** 行 —— 前 4 行都只有右半部分宽。

**根因**：知乎给封面带了 **`margin-bottom: 4px`**。浮动的**影响高度 = `margin-top + height + margin-bottom`**，
只要它超过 `N × 行高`，第 N+1 行的**行框**就会被压住、跟着缩成窄列 —— 看上去就像图片占了 N+1 行。
实测：`84 + 4 + 4 = 92 > 84` ⇒ 第 4 行也被挤窄。

**逐档实测**（同一张卡片，数「被挤成窄列的文字行数」）：

| 配置 | 图片 | 窄列行数 | 顶偏差 | 图底 ↔ 第 4 行文字顶 |
| --- | --- | --- | --- | --- |
| v1.2.4（h=84, mb=4）| 152×84 | **4 行** ✗ | 0 | — |
| 缩小到 h=76, mb=4 | 138×76 | 3 行 ✓ | 0 | 8px 缝 |
| h=80, mb=0 | 145×80 | 3 行 ✓ | 0 | 4px 缝 |
| h=82, mb=0 | 148×82 | **4 行** ✗ | 0 | — |
| **h=84, mb=−4（本版取此）** | **152×84** | **3 行 ✓** | **0** | **0（贴齐）** |

⇒ **图片不必缩小**：只要把知乎那 4px 抵消掉（`margin-bottom: -4px`），
`84 + 4 − 4 = 84` 恰好等于 3 × 行高，于是「3 行高 / 顶底对齐 / 只占 3 行」三者同时成立。

> 用户原本的提议是「把图片再缩小一点点」，实测那样也能让第 4 行回全宽（h=76 ⇒ 138×76），
> 但会白白牺牲 14px 宽并留一条 8px 的底缝 —— 抵消 margin-bottom 是更彻底的解法。

**真机复核（实装 1.2.5）**：封面 **152×84**、高 ÷ 行高 = **3.000**、**窄列行数 3**、全宽行数 4、
顶偏差 **0**、图底与第 4 行文字顶距离 **0**，图片右侧文字可用宽仍是 **174px**（未因本版变化）。

## 6. v1.2.6 修正：底边要对齐**第 N 行文字的底部**，而不是第 N+1 行的行框顶

**现象**（用户）：图片底部跟第 3 行文字底部没有对齐，图片跟第 4 行文字看起来很挤。

**原因**：v1.2.5 把高度取成 `N × 行高`（= 84px），图片底边落在**第 4 行的行框顶**上。
但一个行框 28px 里**字形盒只有约 21px**、上下各留半行距 —— 所以图片底边其实比第 3 行字形底
**还低约 7px**，正好压在第 4 行文字上方。实测：`图底 − 第3行文字底 = +7.4px`。

**改法**：高度改成 `N × 行高 − 7px`（`7px ≈ 行高 − 字形盒高`，**只减一次** —— 行与行之间的
间距本来就该留着）。这样图片从第 1 行**字形顶**起、到第 N 行**字形底**止。

| 高度 | 图底 − 第 3 行文字底 | 图底 − 第 4 行文字顶 | 窄列行数 |
| --- | --- | --- | --- |
| 84（v1.2.5）| **+7.4**（压低、挤住第 4 行）| +0.7 | 3 |
| 78 | +1.4 | −5.3 | 3 |
| **77（本版）** | **+0.4（对齐）** | **−6.3（留出空隙）** | **3** |
| 76 | −0.6 | −7.3 | 3 |

**真机复核（实装 1.2.6）**：图片 **139×77**、窄列 3 行 / 全宽 3 行、
`图顶 − 首行文字顶 = +0.7`、`图底 − 第 3 行文字底 = +0.4`、`图底 − 第 4 行文字顶 = −6.3`；
图片右侧文字可用宽由 174px 增到 **187px**（图片略矮的附带好处）。

## 7. v1.2.7 修正：对齐**字形墨迹盒**，而不是「内联盒」

**现象**（用户）：图片还能再小一点；图片底边仍比第 3 行文字底部靠下，且图片顶比第 1 行文字高了
一丁点。

**原因**：v1.2.6 用的是**内联盒**（`getClientRects()` 返回的框，由字体的 ascent/descent 决定），
而眼睛看到的是**字形墨迹盒**。16px 字体实测：

| 盒 | 高 | 组成 |
| --- | --- | --- |
| 行框 | 28px | 内联盒 + 上下半行距 |
| 内联盒 | **22px** | 字体 ascent 17 + descent 5 |
| **字形墨迹盒** | **15px** | canvas `actualBoundingBoxAscent 14` + `Descent 1` |

字形顶比内联盒顶低 **3px**、字形底比内联盒底高 **4px** —— 所以按内联盒对齐，图片会**两端都「冒出去」**。
实测（v1.2.6 的 h=77）：`图顶 − 行1字形顶 = −2.32`（高出）、`图底 − 行3字形底 = +3.68`（低出）
—— 与用户的描述完全吻合。

**改法**：高度 `(N−1) × 行高 + 字形盒高`，等价于 **`N × 行高 − 13px`**（13 = 行高 28 − 字形盒 15）；
`margin-top` 由 4px 调到 **6.3px**（行框顶 → 字形顶 = 半行距 3 + 字形顶偏移 3）。

| 版本 | 图片 | 图顶 − 行1字形顶 | 图底 − 行3字形底 |
| --- | --- | --- | --- |
| v1.2.6（77px, mt 4）| 139×77 | −2.32（高出）| +3.68（低出）|
| **v1.2.7（71px, mt 6.3）** | **128×71** | **−0.02** | **−0.02** |

**真机复核（实装 1.2.7）**：图片 **128×71**、两端偏差均 **−0.02px**；旁排仍是 3 行；
图片右侧文字可用宽 187 → **198px**。

> **怎么量字形盒**：`canvas.measureText('国')` 取 `actualBoundingBoxAscent / Descent` 得字形墨迹；
> 而内联盒顶 = 基线 − `fontBoundingBoxAscent`，据此换算出字形顶/底相对内联盒顶的偏移。
> ⚠️ 与文字做「行对齐」一定要先想清是跟**行框**、**内联盒**还是**字形盒**对齐 —— 三者 28 / 22 / 15px
> 差很多，本功能先后踩过前两个坑（§6 与本节）。
