# v1.2.8 · 问题页「关注问题 / 写回答 / 邀请回答」同排

## 1. 现象

用户：问题页页首这三个按钮不在同一行，「现在这样好难看」。

## 2. 取证（真机 CDP 实测，列宽 358）

| 按钮 | 宽 | 所在容器 | 行 |
| --- | --- | --- | --- |
| 关注问题 | 96 | `.QuestionButtonGroup` | 第 1 行 |
| 写回答 | 96 | `.QuestionButtonGroup` | 第 1 行 |
| **邀请回答** | **111** | **`.QuestionHeaderActions`** | **第 2 行** |

- 三个按钮**分属两个容器**（知乎桌面版本靠并排排布），而**本脚本自己的 CSS**把
  `.QuestionHeader-footer-inner` 强制成 `flex-direction: column` ⇒ 两个容器只能上下堆叠，
  「邀请回答」于是被挤到第 2 行，还和「好问题 / 评论」混在一行。
- 合计宽 `96 + 16 + 96 + 8 + 111 = 327`（含边距约 351）**≤ 358 ⇒ 一行放得下**。

## 3. 改法

```css
.QuestionHeader-footer-inner {
  flex-direction: row !important; flex-wrap: wrap !important; align-items: flex-start !important;
}
.QuestionHeaderActions { display: contents !important; }   /* 解散这个排布壳 */
```

> ⚠️ **实测：只把外层改成 `row` 是无效的**（三者行数仍是 2）—— `.QuestionHeaderActions`
> 作为一个整体（含「邀请回答 + 好问题 + 评论 + 分享」）会整个换到下一行。
> 只有 `display: contents` 把它**解散**，其中的按钮才能真正参与第一行的排布。
> 该容器只是个排布壳、没有自己的背景/边框，解散是安全的。

## 4. 实测

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 三者行数 | 2 | **1** |
| 三个按钮的 T | 309 / 309 / **342** | **309 / 309 / 309** |
| 三者横向范围 | `36..244` + `36..147` | `36..**354**` ≤ 358 ✓ |
| 「好问题 / 评论 / 分享」| 与「邀请回答」挤在同一行 | 自然换到第 2 行 |

## 5. v1.2.9 修正：均匀分布（用满整行、不再有「贴在一起」）

**现象**（用户）：右边两个按钮挤在一起；最左侧还有空白可以利用，希望按钮区整体左移并均匀分布。

**真正的层级**（v1.2.8 只改到了外层，所以没解决挤压）：

```
.QuestionHeader-footer-inner            ← v1.2.8 改的是这一层
  └ .QuestionHeader-footer-main         ← 真正承载按钮的 flex 行（还有 20px 左内边距）
      ├ .QuestionButtonGroup            （关注问题 + 写回答）— 还带 -8px 右外边距！
      └ .QuestionHeaderActions          （邀请回答 + 好问题 + 评论 + 分享）
```

- ⚠️ 类名是 **`.QuestionHeader-footer-main`**（`-main` 后缀），**不是** `.QuestionHeader-footer` ——
  v1.2.8 的选择器打偏了，只是恰好让三个按钮同排，间距问题没碰到。
- 「右边两个贴在一起」的根因：`.QuestionButtonGroup` 带 **`margin-right: -8px`**，把「邀请回答」
  拉过来贴着「写回答」（实测间距 `[16, 0]`）。

**改法**（三层一起动）：

```css
.QuestionHeader-footer-inner { flex-direction: row; flex-wrap: wrap; align-items: flex-start;
                               padding: 0; margin-right: 0; }   /* 去掉 0 16px 内边距与 -32px 右外边距 */
.QuestionHeader-footer-main  { display: flex; flex-wrap: wrap; justify-content: space-between;
                               column-gap: 10px; padding-left: 0; padding-right: 0; }
.QuestionButtonGroup, .QuestionHeaderActions { display: contents; }   /* 解散两个排布壳 */
.QuestionHeader-footer-main button { margin-left: 0; margin-right: 0; } /* 清掉按钮自带 8px 外边距 */
```

**实测**

| 指标 | v1.2.8 | **v1.2.9** |
| --- | --- | --- |
| 三者行数 | 1 | 1 |
| 三按钮横向 | 36..132 / 148..244 / **244..354** | **0..96 / 124..220 / 247..358** |
| 两处间距 | `[16, **0**]`（贴住）| **`[28, 27]`（均匀）** |
| 左空 / 右空 | 36 / 4 | **0 / 0**（用满整行）|

**验证**：`scripts/test-question-actions.js` 增加 3 条断言（间距差 ≤4px、两处间距为正、左右空档 ≤4px），
**12 / 12 通过**。本版只跑了这一套（改动只影响问题页页首，见「验证范围」约定）。

## 7. v1.2.10 修正：两侧留白对齐**正文文字区**

**现象**（用户）：上一版把左右内边距清零后，按钮区**顶到屏幕边缘**了；两侧应该留白，
**至少不能超出正文文字区**。

**取证**：正文文字区（`.AnswerItem` / `.RichText`）实测是 **20..338** —— 左右各 20px 内缩。
而 v1.2.9 的按钮区是 `0..358`，确实顶到边。

**改法**：给按钮行加回 `padding: 0 20px`（与正文对齐）。
但这样一来可用宽只剩 318，而三个按钮原样占 303 + 两处 10px 间隙 = 323 > 318 ⇒ **会换行**
（实测 G 档就是这样）。所以同时把按钮自带的左右 16px 内边距收到 **13px**
（每个各窄 6px、合计省 18px，**内容盒不变 ⇒ 文字不会被裁**）。

| 指标 | v1.2.9 | v1.2.10 的 G 档（只加留白）| **v1.2.10 实际（H 档）** |
| --- | --- | --- | --- |
| 三按钮 | 0..96 / 124..220 / 247..358 | 换行（2 行）✗ | **20..116 / 130..220 / 233..338** |
| 两侧留白 | **0 / 0** ✗ | 20 / 20 | **20 / 20** ✓ |
| 与文字区（20..338）| 超出 ✗ | — | **完全一致** ✓ |
| 两处间距 | 28 / 27 | — | **14 / 13** ✓ |

**验证**：`test-question-actions.js` 把「用满整行（≤4px）」换成两条新断言
——「两侧都有留白（≥8px）」与「按钮区不超出正文文字区」。
**改前 11 passed / 2 failed（左空 0、右空 0）、改后 13 / 0**，判别力已确认。
按「验证范围」约定，本版仍**只跑这一套**。
