# v1.4.19 — 个人主页（Profile）单列化

日期：2026-10-23 ｜ 环境：MuMu（小米 13 同参）+ Kiwi 137 + 暴力猴 2.49.0，登录态，`/people/toperp/posts`，桌面模式。

## 现象（用户要求适配的页面）

- 头部与内容区右侧被屏幕裁掉一条（量到 `.ProfileHeader` / `.Profile-main` 宽 390 > 列宽 358，溢出 32px）；
- 「关注他」按钮压住签名文字；
- 顶部导航「专栏 / 圈子」被裁、无法滚动查看。

## 根因（实测，列宽 358）

| # | 问题 | 实测数据 |
| --- | --- | --- |
| 1 | `.ProfileHeader` / `.Profile-main` 带 `margin-right:-32px`（桌面头图出血设计），且 `box-sizing:content-box` + `width:358px` + 左右 padding 各 16px ⇒ 实际 358+32=390px | 右缘 390，被裁 32px |
| 2 | 头像 `position:absolute` 挂在 `.ProfileHeader-main` 左上，content 靠 `border-left:164px solid transparent` 让位 ⇒ 直接清 border-left 会让名字/签名移到头像**下面被整块盖住**（第一版修法就踩了这个坑，名字 56..158 全部重叠在头像区域内） | 头像 36..204×179..347 |
| 3 | `.ProfileHeader-contentBody` 写死 `width:524px`（桌面正文宽）；contentHead 里的 `.Button--plain` 被 absolute 定到 `right:0`，窄列下压住签名 | contentBody 524 > 326 |
| 4 | 顶部导航 nav 463px 宽，其壳层（flex 中列）被压到 188px 且 `overflow:visible` ⇒ 溢出部分被 header 的裁剪层裁掉 | nav 100..563，可见只到 358 |

## 修法（全部稳定类名；仅两条导航壳层规则用了 emotion hash，失效时只是导航不可滚，不影响内容）

```css
.ProfileHeader, .Profile-main { margin-right: 0 !important; box-sizing: border-box !important; }
.ProfileHeader-main { display: block !important; }
.ProfileHeader-avatar { position: static !important; display: block !important; margin: 0 auto 4px !important; }
.ProfileHeader-content { border-left: 0 !important; padding-left: 16px !important; padding-right: 16px !important; padding-top: 8px !important; margin-top: 4px !important; }
.ProfileHeader-contentHead { max-width: 100% !important; }
.ProfileHeader-contentHead .Button--plain { position: static !important; }
.ProfileHeader-contentBody { width: auto !important; max-width: 100% !important; max-height: none !important; }
.AppHeader nav { overflow-x: auto !important; overflow-y: hidden !important; scrollbar-width: none !important; white-space: nowrap !important; }
.AppHeader nav::-webkit-scrollbar { display: none !important; }
.AppHeader nav a { white-space: nowrap !important; flex: 0 0 auto !important; }
.AppHeader nav.css-72pd91 { width: max-content !important; min-width: 0 !important; flex: 0 0 auto !important; }
.AppHeader .css-51utkw { overflow-x: auto !important; display: flex !important; flex: 1 1 0 !important; min-width: 0 !important; }
```

关键取舍：**上下排布**。桌面的「左头像 168px + 右内容」在 358px 列宽放不下——保留并排会把内容压到 82px，按钮组（213px）必然压住文字。头像独立成行居中后，名字/签名/职业/按钮各占整行，互不遮挡。

## 验证（`--installed` 装机终验，2026-10-23）

- `check-injected.js "people/toperp"`：90 条规则注入 ✓
- `.ProfileHeader` / `.Profile-main`：`0..358`，右侧不再溢出；整页无横向溢出（`scrollWidth <= clientWidth`）
- 头像 36..322 居中独立成行；名字 52..154；contentBody 254px 全宽；「关注他 / 发私信」按钮并排（93..306）完整可见
- 顶部导航可横向滚动（壳层 `scrollWidth 651 > clientWidth 188`），「专栏 / 圈子」滑动可达
- 视觉终验：头像居中 → 名字+签名同行 → 职业行 → 按钮行，逐项截图核对

## 排查中顺手修掉的环境坑（记录在案）

- people 页标签曾出现 CDP 求值挂死（`1+1` 30s 无响应）——文档已知的「长会话 renderer 挂死」症状，`am force-stop` 重启 Kiwi 后恢复；
- 关闭挂死标签重开后恢复正常测量。
