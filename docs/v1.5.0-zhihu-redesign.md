# v1.5.0 — 适配知乎 2026-11 改版（左侧栏 + 新顶部导航）

## 背景

知乎桌面版改版：首页/问答/搜索/个人主页等页面新增**左侧栏**（40px 图标竖条 + 58px 展开面板），
顶部导航换成 `HEADER.LeanAppHeaderBar`（旧 `.AppHeader` 不再渲染），内容区壳变成
`div.css-syn8px > div.css-t9zu9r > div.css-12c3wuv > main.App-main` 的多层 flex 结构，
且各层带桌面写死宽（内容区 1104px、主列 784px）。旧脚本的选择器与宽度假设全部失配，
页面在窄列下呈 3~4 列横向平铺。

## 决策：左侧栏隐藏，不搬运（方案 A，用户 2026-11-19 确认）

- 左栏全部入口（首页/关注/热榜/圈子/专栏…）在新顶部导航与内容区 tab 里都有，搬运属重复入口；
- DOM 搬运需要与 SPA 重渲染对抗（observer 反复搬回），脆弱且高维护成本；
- 隐藏即回到旧版已验证稳定的单列布局。

## 改动清单

### 1. 新顶部导航适配（`.LeanAppHeaderBar`，语义类名稳定）
static、满宽、内部可横滚、隐藏滚动条 —— 与旧 `.AppHeader` 同款待遇（CSS）。

### 2. 左侧栏隐藏 + 内容区收宽（`hideLeftNav()`，JS 几何识别）
类名全是 emotion hash，无法选择器化，按几何特征在 JS 里处理：
- 定位内容壳：从 `main.App-main` 向上找第一个「flex 且子元素 ≥3」的祖先（`css-syn8px`）；
- 隐藏其子级中「宽 ≤64px 且全高」的竖条/面板/隔离壳（40/58/0px 三种形态）；
- 内容区壳（`css-t9zu9r`，桌面写死 1104px）设 `width:auto; max-width:100%`；
- **main 的直接父壳**（`css-12c3wuv`）设 `flex:1 1 auto; min-width:0`——
  它是 flex row 的子项，窄列里会被 flex-shrink 压到 38px（people/search 页实测，
  main 跟着 38px、文字全部逐字竖排、页面高 6 万 px）；
- 隐藏 main 父壳的兄弟中「全高 ≥300、宽 >200」的元素——即内容壳内右栏
  （people/search 页 `ASIDE.css-14mwtba` 320px `flex:0 0 auto` 拒绝收缩，是挤压元凶）。
  与旧 `hideSideRails` 的「内容在前、栏在后」假设一致，新旧版式都遵守。

### 3. 问题页：按钮行左侧竖排数据窄条隐藏（`hideQuestionDataRail()`）
新版问题头按钮行左侧有一个 **24.5px 宽的窄壳**（hash 类名），桌面版竖排塞着
「好问题」星标 / 「37 条评论」/「3691 关注」/「1.1 亿浏览」；窄列下逐字竖排并与
按钮行糊成一片。隐藏依据：关注按钮就在右侧、评论数在各回答底部、浏览数价值低。
识别（不依赖 hash）：从 `.FollowButton` 向上穿过 `display:contents` 壳找到按钮行，
隐藏其中「宽 ≤40px 且含按钮/数据子项」的非按钮容器。

### 4. 个人主页：新版吸顶 tab 条 portal 隐藏
旧规则（v1.4.20）依赖 `.css-1ndlr1n` hash，改版后失效。新版 portal 壳是
`.ProfileMain-contents`（语义类名，稳定）——`display:none`。
内容区本有完整同款 tab 条（`.ProfileMain-header > ul.Tabs`）。

### 5. 圈子页：成员头像行换行（`wrapRingMemberRows()`）
圈子卡片里「圈友」一行是 flex nowrap，每成员 84px、40 个成员排到 3360px
（溢出屏幕至 746px+）。识别（不依赖 hash）：`.Topstory-mainColumnCard` 下
「flex + nowrap + 子项 ≥4 + 绝大多数子项含 svg/链接 + scrollWidth > clientWidth」
的行，改 `flex-wrap:wrap`。
⚠️ 踩坑：首版用「子项宽度相近」判定，实测行内首个子项 60px、其余 84px，判定漏行——
放宽为「含图标子项数 ≥ 总数−2」即可。

### 6. `CFG.forceSW` 调试口子
桌面 Chrome / 模拟器的 emulation 视口与真机口径不同（`visualViewport.scale` 恒 1、
`curScreenW` 被算成整个视口宽），自动校准会把 SW 定成视口宽、失去窄列语境。
`forceSW: 358` 可在桌面环境复现真机布局，audit 脚本（`scripts/audit-all.js`）注入前
replace 此值。真机默认 `forceSW: 0`（自动），行为不变。

## 验证

`node scripts/audit-all.js`（MuMu Kiwi + CDP，`forceSW=358` 真机口径）：

### 测试基建坑（供后来者）

- **Chrome137 (Kiwi) 上 `Page.addScriptToEvaluateOnNewDocument` 不生效**——
  必须 navigate 后直接 `Runtime.evaluate` 脚本体（脚本顶部 `__z2mStop` 有幂等保护）。
- **emulation 截图伪影**：`html zoom` × `setPageScaleFactor` × `captureScreenshot`
  组合会把渲染平铺成多份（截图里的「3 列内容」不是真实布局！）。
  DOM 坐标断言才是真相；视觉验证用「zoom 置 1 + clip 截图」的等效手段。
- CDP 新建的 target 在 Kiwi 里导航不可靠（停在 about:blank），须复用已有标签页。
- audit 的溢出检测必须过滤「被列内滚动/裁剪容器合法裁剪」的元素
  （横滑轮播卡、tab 条滚动区都是合法溢出），否则误报上百个。

## 首屏闪烁修复（v1.5.4，2026-11-19 用户反馈）

用户反馈：打开页面时先显示左侧工具条、随后隐藏，造成闪烁。

根因：新版左栏是 emotion hash 类名，当初认为「hash 不能写选择器」，只靠 JS
`hideLeftNav()`（tick 300ms 去抖 + 等 DOM 就绪）隐藏——首帧必然先画一次。

修法：hash 类名**在当前构建内是稳定的**，且样式表 document-start 注入、先于任何
渲染。把当前实测 hash 加进 CSS（`.css-uf7ueu, .css-txb60n, .css-14mwtba, .css-1o4togs
{ display:none !important }`），首屏直接不画；JS hideLeftNav 保留（几何识别），
hash 未来变化时只是退回「闪一下再隐藏」，不会失效。

验证：暴力猴更新到 1.5.4 后，导航首页并以 150ms 粒度轮询左栏 computed display——
首个可测帧即为 none（此前 JS 路径首个可测帧也是 none，但轮询粒度不够捕捉闪烁帧；
CSS 路径从渲染管线层保证首帧不画）。8 页走查无回归。

## 顶部导航 tab 消失 + 问题页贴边修复（v1.5.5，2026-11-19 用户反馈）

1. **顶部「关注/推荐/热榜」消失**：tab 容器（hash css-1pbgcc2）flex-basis 写死 704px，
   在 358px 窄行里被 flex-shrink 压成 0 宽，三个 tab 全部 0 宽消失。
   修法：`.LeanAppHeaderBar div, nav, a { flex-shrink: 0 }` —— 导航壳内所有块禁止收缩，
   行内容靠壳的 overflow-x 横滑（与个人主页顶栏同款策略）。验证：tab 0px → 34px。

2. **问题页元素贴边**：H1 标题/摘要/写回答按钮/赞同全部 x=0 顶到屏幕边。
   根因：`CFG.bleedEdges`（旧版用户确认的「块铺满整列」）的前提是块**自带**内边距
   （旧版问答块 22px）——2026-11 改版后新版问题页把块内边距去掉了，前提失效。
   首页卡片仍自带 16px padding 不受影响。
   修法：问题页豁免——`.QuestionPage { padding: 0 12px }`，其余页面 bleedEdges 保持。

3. 8 页走查无回归（tab 34px、问题页 main 0..358 满宽 0 溢出）。

## 留白收敛（v1.6.0，2026-11-19 用户反馈「两侧留白太多」）

实测：新版知乎把内容壳左右 padding 加到 40px（首页 TopstoryItem/问题页 css-1esd2rv），
叠加 .QuestionPage 12px（v1.5.5 贴边修复）= 每侧 52px，内容只占 71%（254/358）。

新增 `normalizePadding()`：main 深层壳（:scope 4 层内）padding > 24px 的压到 12px。
内容宽 254 → 310~334，每侧留白 24px（问题页）/12px（首页），利用率 87~93%。
保留呼吸感不顶边（v1.5.5 贴边修复不回退）。8 页走查无回归。

## 留白统一 12px（v1.6.1/1.6.2，2026-11-19 用户反馈「首页留白没改、各页要一致」）

v1.6.0 的 normalizePadding 用 `:scope` 4 层深度限制，首页 `.Topstory-mainColumn` 的
40px padding 在 main 深层漏网——首页留白没变。修法：全量扫描 main 内所有 div/section/
article（padding>24 压 12，WeakSet 记忆化对静态 CSS 属性安全）。
同时删掉 `.QuestionPage` 的 12px 叠加层（v1.5.5 加的）——壳统一 12px 后再叠就是 24px。

最终：**全站留白统一 12px**。首页/问题页/专栏/搜索 内容 12..346（宽 334，利用率 93%）。
8 页走查全 PASS。
